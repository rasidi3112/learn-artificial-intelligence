Módulo 16 / 17

Agentes de IA: Modelos que Actúan

Comprende cómo los LLM planifican pasos, llaman herramientas y completan tareas dentro de límites de seguridad claros.

Nivel: Intermedio Duración: 25 min

01 Del Chatbot al Agente

Un chatbot responde un mensaje y se detiene. Un agente ejecuta un LLM en bucle: lee el objetivo, elige un paso, llama a una herramienta, lee el resultado y decide el siguiente paso hasta terminar la tarea. El patrón ReAct alterna razonamiento y acción. Ejemplo: un agente de soporte consulta el estado de un pedido, lee la política de devoluciones y prepara un reembolso. Usa un agente solo cuando los pasos no se pueden fijar de antemano; un flujo fijo es más barato y fácil de probar como workflow normal.

02 Llamadas a Herramientas y Esquemas de Funciones

Cada herramienta se describe con un nombre, una explicación y un JSON Schema para sus argumentos, por ejemplo get_order(order_id: string). El modelo no ejecuta código por sí mismo: devuelve una llamada estructurada, la aplicación valida los argumentos y la ejecuta, y el resultado vuelve al modelo. El Model Context Protocol (MCP) estandariza cómo las aplicaciones ofrecen herramientas y datos a los modelos. Descripciones claras, argumentos validados y mensajes de error informativos suelen importar más que la elección del modelo.

03 Memoria, Planificación y Multiagentes

La memoria a corto plazo es el historial de la conversación en la ventana de contexto; la memoria a largo plazo suele guardarse en una base de datos o un vector store y se recupera cuando es relevante. En tareas largas, el agente puede dividir el objetivo en un plan por pasos y actualizarlo tras cada resultado. El patrón orquestador-trabajador reparte subtareas entre varios agentes en paralelo, por ejemplo para investigar varias fuentes a la vez. Cada agente extra suma coste de tokens, latencia y puntos de fallo, así que empieza con uno sencillo.

04 Seguridad y Evaluación de Agentes

El texto de páginas web, correos o documentos puede contener inyección de prompts que ordene al agente hacer otra cosa. Da a las herramientas el mínimo privilegio posible, ejecuta código en un sandbox, limita el número de pasos y el presupuesto, y pide aprobación humana antes de acciones difíciles de revertir, como transferir dinero o borrar datos. Guarda una traza de cada paso para auditoría. Evalúa los agentes con tareas reales y mide la tasa de éxito, los pasos, el coste y los errores graves; benchmarks como SWE-bench y τ-bench siguen el mismo enfoque.
