AI 에이전트: 행동하는 모델

LLM이 단계를 계획하고 도구를 호출하며 명확한 안전 범위 안에서 작업을 끝내는 방법을 이해합니다.

레벨: 중급 소요시간: 25 분

01 챗봇에서 에이전트로

챗봇은 메시지 하나에 답하고 멈춥니다. 에이전트는 LLM을 루프 안에서 실행합니다. 목표를 읽고, 단계를 고르고, 도구를 호출하고, 결과를 읽은 뒤 작업이 끝날 때까지 다음 단계를 정합니다. ReAct 패턴은 추론과 행동을 번갈아 수행합니다. 예를 들어 고객지원 에이전트는 주문 상태를 확인하고, 반품 정책을 읽은 뒤, 환불을 준비합니다. 단계를 미리 정할 수 없을 때만 에이전트를 쓰세요. 정해진 흐름이라면 일반 워크플로가 더 싸고 테스트하기도 쉽습니다.

02 도구 호출과 함수 스키마

각 도구는 이름, 설명, 인자에 대한 JSON Schema로 기술합니다. 예: get_order(order_id: string). 모델은 코드를 직접 실행하지 않습니다. 구조화된 호출을 반환하면 애플리케이션이 인자를 검증해 실행하고, 그 결과를 다시 모델에 보냅니다. Model Context Protocol(MCP)은 애플리케이션이 모델에 도구와 데이터를 제공하는 방식을 표준화합니다. 명확한 도구 설명, 검증된 인자, 유용한 오류 메시지가 모델 선택보다 에이전트의 성패를 더 크게 좌우하는 경우가 많습니다.

03 메모리, 계획, 멀티 에이전트

단기 메모리는 컨텍스트 윈도우 안의 대화 기록이고, 장기 메모리는 보통 데이터베이스나 벡터 스토어에 저장했다가 필요할 때 불러옵니다. 긴 작업에서는 에이전트가 목표를 단계별 계획으로 나누고 결과가 나올 때마다 갱신할 수 있습니다. 오케스트레이터-워커 패턴은 하위 작업을 병렬로 일하는 여러 에이전트에게 나눠 줍니다. 예를 들어 여러 출처를 동시에 조사하는 경우입니다. 에이전트가 하나 늘 때마다 토큰 비용, 지연, 실패 지점이 늘어나므로 단순한 에이전트 하나로 시작하세요.

04 에이전트의 안전과 평가

웹 페이지, 이메일, 문서의 텍스트에는 에이전트에게 다른 일을 시키는 프롬프트 인젝션이 숨어 있을 수 있습니다. 도구에는 최소한의 권한만 주고, 코드는 샌드박스에서 실행하고, 단계 수와 예산에 상한을 두고, 송금이나 데이터 삭제처럼 되돌리기 어려운 작업 전에는 사람의 승인을 받으세요. 감사를 위해 모든 단계의 트레이스를 남깁니다. 에이전트는 실제 작업 모음으로 평가하고 성공률, 단계 수, 비용, 치명적 오류를 측정합니다. SWE-bench와 τ-bench 같은 벤치마크도 같은 접근을 씁니다.
