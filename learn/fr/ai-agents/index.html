Module 16 / 17

Agents IA : des Modèles qui Agissent

Comprendre comment les LLM planifient des étapes, appellent des outils et accomplissent des tâches dans des limites de sécurité claires.

Niveau: Intermédiaire Durée: 25 min

01 Du Chatbot à l’Agent

Un chatbot répond à un message puis s’arrête. Un agent fait tourner un LLM en boucle : il lit l’objectif, choisit une étape, appelle un outil, lit le résultat et décide de l’étape suivante jusqu’à la fin de la tâche. Le schéma ReAct alterne raisonnement et action. Exemple : un agent de support vérifie le statut d’une commande, lit la politique de retour, puis prépare un remboursement. N’utilisez un agent que si les étapes ne peuvent pas être fixées d’avance ; un flux fixe coûte moins cher et se teste plus facilement comme workflow classique.

02 Appels d’Outils et Schémas de Fonctions

Chaque outil est décrit par un nom, une explication et un JSON Schema pour ses arguments, par exemple get_order(order_id: string). Le modèle n’exécute pas de code lui-même : il renvoie un appel structuré, l’application valide les arguments et l’exécute, puis le résultat revient au modèle. Le Model Context Protocol (MCP) standardise la façon dont les applications exposent outils et données aux modèles. Des descriptions claires, des arguments validés et des messages d’erreur utiles comptent souvent plus pour la réussite d’un agent que le choix du modèle.

03 Mémoire, Planification et Multi-Agents

La mémoire à court terme est l’historique de la conversation dans la fenêtre de contexte ; la mémoire à long terme est en général stockée dans une base de données ou un vector store et récupérée quand elle est utile. Pour les tâches longues, l’agent peut découper l’objectif en plan par étapes et le mettre à jour après chaque résultat. Le schéma orchestrateur-exécutants confie des sous-tâches à plusieurs agents en parallèle, par exemple pour explorer plusieurs sources à la fois. Chaque agent supplémentaire ajoute coût en tokens, latence et points de défaillance : commencez par un seul agent simple.

04 Sécurité et Évaluation des Agents

Le texte de pages web, d’e-mails ou de documents peut contenir une injection de prompt qui pousse l’agent à faire autre chose. Donnez aux outils le moins de privilèges possible, exécutez le code dans un bac à sable, plafonnez le nombre d’étapes et le budget, et exigez une validation humaine avant les actions difficiles à annuler comme un virement ou une suppression de données. Conservez une trace de chaque étape pour l’audit. Évaluez les agents sur un ensemble de tâches réelles en mesurant le taux de réussite, le nombre d’étapes, le coût et les erreurs graves ; des benchmarks comme SWE-bench et τ-bench suivent la même logique.
