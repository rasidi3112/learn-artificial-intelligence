KI-Agenten: Modelle, die handeln

Verstehen, wie LLMs Schritte planen, Tools aufrufen und Aufgaben innerhalb klarer Sicherheitsgrenzen erledigen.

Stufe: Mittel Dauer: 25 Min

01 Vom Chatbot zum Agenten

Ein Chatbot beantwortet eine Nachricht und hört auf. Ein Agent lässt ein LLM in einer Schleife laufen: Er liest das Ziel, wählt einen Schritt, ruft ein Tool auf, liest das Ergebnis und entscheidet über den nächsten Schritt, bis die Aufgabe erledigt ist. Das ReAct-Muster wechselt zwischen Denken und Handeln. Beispiel: Ein Support-Agent prüft den Bestellstatus, liest die Rückgaberichtlinie und bereitet eine Erstattung vor. Setzen Sie Agenten nur ein, wenn sich die Schritte nicht vorab festlegen lassen; ein fester Ablauf ist als normaler Workflow günstiger und leichter zu testen.

02 Tool Calling und Funktionsschemas

Jedes Tool wird mit einem Namen, einer Erklärung und einem JSON Schema für seine Argumente beschrieben, etwa get_order(order_id: string). Das Modell führt selbst keinen Code aus: Es gibt einen strukturierten Aufruf zurück, die Anwendung prüft die Argumente und führt ihn aus, und das Ergebnis geht zurück an das Modell. Das Model Context Protocol (MCP) standardisiert, wie Anwendungen Modellen Tools und Daten bereitstellen. Klare Tool-Beschreibungen, geprüfte Argumente und aussagekräftige Fehlermeldungen entscheiden oft mehr über den Erfolg als die Modellwahl.

03 Gedächtnis, Planung und Multi-Agenten

Das Kurzzeitgedächtnis ist der Gesprächsverlauf im Kontextfenster; das Langzeitgedächtnis liegt meist in einer Datenbank oder einem Vector Store und wird bei Bedarf abgerufen. Bei langen Aufgaben kann ein Agent das Ziel in einen Schritt-für-Schritt-Plan zerlegen und ihn nach jedem Ergebnis anpassen. Das Orchestrator-Worker-Muster verteilt Teilaufgaben auf mehrere parallel arbeitende Agenten, etwa um mehrere Quellen gleichzeitig zu recherchieren. Jeder zusätzliche Agent erhöht Token-Kosten, Latenz und Fehlerquellen, also beginnen Sie mit einem einfachen Agenten.

04 Sicherheit und Bewertung von Agenten

Text aus Webseiten, E-Mails oder Dokumenten kann Prompt Injection enthalten, die den Agenten zu etwas anderem verleitet. Geben Sie Tools möglichst wenige Rechte, führen Sie Code in einer Sandbox aus, begrenzen Sie Schritte und Budget, und holen Sie vor schwer umkehrbaren Aktionen wie Überweisungen oder dem Löschen von Daten eine menschliche Freigabe ein. Protokollieren Sie jeden Schritt für Audits. Bewerten Sie Agenten anhand realer Aufgaben und messen Sie Erfolgsquote, Schrittzahl, Kosten und schwere Fehler; Benchmarks wie SWE-bench und τ-bench gehen genauso vor.
